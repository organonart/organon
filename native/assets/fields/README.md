# Field Playback clips (`.bin`) — Organon Field Engine (#407 Tier A)

A **Field Playback** clip is a small, pre-baked, downsampled *visual* animation of a
physical field. Organon's Field Engine generator replays it through the same glyph
lattice as its live PDE simulations (Heat / Wave / Schrödinger / Gray–Scott), stepped
off the host-synced beat clock. Select **PDE preset → "Playback (Dataset)"** in the
Field Engine card, then **Load Field Clip…** to pick a `.bin`.

The clip is **physics-agnostic**: the offline tool (`generate.py`) has already mapped
whatever physical field it chose into two display channels per grid cell —

| channel | meaning | drives |
|---|---|---|
| `c0` | density (≥ 0) | glyph length / brightness |
| `c1` | hue (0..1 turns) | glyph colour (when the clip is flagged *complex*) |

The renderer never runs a solver on these — the frames are baked; it just steps them.

## Data source: PolymathicAI's *The Well*

The intended real-data source is **The Well**, a large collection of physics
simulation datasets released by **PolymathicAI**:

- Repository: <https://github.com/PolymathicAI/the_well>
- License: **CC-BY-4.0** (attribute PolymathicAI / *The Well* when you ship clips
  derived from it).

*The Well* runs are large HDF5 files (many GB). We do **not** vendor them. Instead,
`generate.py` downsamples one field of one run into a tiny `.bin` for playback. Only
the derived, downsampled clips (and the synthetic demo) live in this repo.

## What ships in the repo

- **`welldemo-swirl.bin`** — a synthetic 96×96 × 120-frame swirling/advecting field,
  generated by `generate.py --demo` (pure Python stdlib, no numpy/h5py). It exists so
  the gallery is never empty and the pipeline is exercised without downloading data.

## `.bin` format

Little-endian throughout. A **7-word `u32` header** followed by the `f32` payload:

| offset | field | value |
|---|---|---|
| 0 | `magic` | `0x4F464C43` (ASCII "OFLC") |
| 4 | `version` | `1` |
| 8 | `w` | grid width (1..512) |
| 12 | `h` | grid height (1..512) |
| 16 | `nframes` | frame count (1..4096) |
| 20 | `channels` | `2` (c0, c1) |
| 24 | `complex` | `0` / `1` — hue-tint hint (see below) |
| 28.. | payload | `nframes · h · w · 2` × `f32`, interleaved `c0,c1` per cell, row-major `y*w + x` |

The loader (`native/src/math.rs::FieldClip::from_bytes`) validates the header and
rejects anything malformed or oversize (caps: `w,h ≤ 512`, `nframes ≤ 4096`,
`w·h·nframes ≤ 16,000,000`), so a corrupt file can never crash the render thread.

> **Note on `complex`:** the format spec in the issue lists a 6-word header ending at
> `channels`. This tool adds one trailing header word, `complex` (0/1), so the clip's
> render hint survives a byte round-trip (the `FieldClip` struct carries it). When
> `complex = 1`, cells are tinted by the baked `c1` hue; when `0`, they're tinted by
> normalized density.

## Regenerating

Synthetic demo (runs anywhere, no dependencies):

```bash
python3 generate.py --demo -o welldemo-swirl.bin
```

From a real *The Well* run (needs `numpy` + `h5py`, and a downloaded `.hdf5`):

```bash
pip install numpy h5py
python3 generate.py --input path/to/run.hdf5 --field velocity \
    --width 96 --height 96 --frames 120 -o myclip.bin
```

Inspect a run's datasets first with `h5ls -r run.hdf5` and pass the matching field
name substring via `--field`. After regenerating, re-run `native/deploy.sh` on the
Mac to install the gallery into `~/Library/Application Support/OrganicMath/fields/`.
