### The legibility fixtures are pinned to LF, and the test that edits one byte-for-byte no longer depends on the checkout

`legibility::tests::parse_errors_name_the_line` embeds `tests/fixtures/asymmetric.txt` with `include_str!` and breaks it on purpose by exact substring — `replace("order top-down\n", "")` — to check the parser names the offending line. On a checkout with `core.autocrlf=true` the fixture arrives as CRLF, the `\n` pattern matches nothing, the "broken" fixture parses cleanly, and `unwrap_err` panics. It passed for the worker that wrote it (the file was born LF in that worktree), it passes on every Linux runner, and it failed on exactly one machine: the coordinator's post-merge gate on `main`, which is what that gate is for.

⚠️ **`str::lines` was never the problem** — it strips `\r\n` — so the parser reads a CRLF fixture correctly; only a test that reaches under the parser to edit bytes is exposed. Two fixes, both kept: `.gitattributes` now declares the fixture directory `text eol=lf`, because a byte-pinned test input must not depend on a client-side setting; and the test normalises `\r\n` before editing, so it stays correct on a checkout that predates the attribute.
